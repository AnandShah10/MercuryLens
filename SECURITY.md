# Security

## How this extension executes external programs

MercuryLens runs external processes (`mmc`, a built Mercury executable,
`mdb`, `mprof`, `mdprof_cgi`). All of it goes through two choke points:

- `extension/src/utils/process.ts` (extension host, one-shot commands)
- `server/src/compiler/mercuryCompilerAdapter.ts` (language server)
- `extension/src/debug/mdbProcess.ts` (the long-lived, interactive `mdb`
  session used by the experimental debug bridge)

All three call Node's `child_process.spawn` with an **argument array** and
`shell: false` — never a concatenated shell string. This means user input
(file paths, module names, values typed into a prompt) is never
interpreted by a shell, which is the class of vulnerability this most
directly guards against (arbitrary command injection via unescaped shell
metacharacters).

## Workspace trust

Every command that builds, runs, or debugs code (`Build/Run/Clean
Project`, the Playground commands, `Debug with mdb`, the experimental
debug session) checks `vscode.workspace.isTrusted` first and refuses in an
untrusted workspace. Purely informational features (hover, navigation,
syntax highlighting, the syntactic diagnostics fallback) are not gated —
they don't execute anything.

## Webviews

Every webview (Call Graph, Module Dependencies, AST Explorer, Mode/Type/
Determinism Information, Playground, Deep Profile) is created with a
strict Content-Security-Policy (`default-src 'none'`, no remote resources,
no `eval`) and communicates with the extension host only via typed
`postMessage` contracts — see `extension/src/views/webviewUtils.ts`.

The Deep Profile view is a partial exception worth calling out
specifically: it displays real HTML output from `mdprof_cgi` (see
`docs/compiler-integration.md#deep-profiling`). That output has its
`<script>`, `<style>`, `<meta>`, and `<base>` tags stripped defensively
before display, and the panel's own CSP still applies — but it is HTML
generated by an external tool rather than solely by this extension, which
is a different trust boundary than the other, fully self-authored
webviews. If you don't trust the `mdprof_cgi` binary on your `PATH`,
don't use that command.

## What this extension deliberately does not do

- It never sends any information anywhere over a network. No telemetry
  (see the README/PACKAGE — none is registered), no external API calls
  beyond spawning local processes.
- It never executes content read from a source file as a shell command.
- It never presents unverified output as compiler-verified (see
  `docs/compiler-integration.md` and `docs/language-server.md` throughout
  for exactly which features are heuristic vs. real compiler output).

## Reporting a vulnerability

This is an independently maintained extension, not an official Anthropic
or Mercury-language project. If you find a genuine security issue (not a
correctness bug — see `CONTRIBUTING.md` for those), open an issue
describing the concern and, if possible, a minimal reproduction. Given
this project's scope (a local development tool that only ever talks to
locally-installed compiler/debugger binaries and the local filesystem),
the realistic threat model is narrow — the areas most worth scrutiny are
the process-spawning choke points and webview message handling listed
above.
